# SF blind system reconstruction

## SYSTEM PURPOSE
An evaluation-harness orchestration procedure that pins immutable scenario inputs, executes scenarios with bounded workers against an isolated system, grades completed artifacts with evidence validation and retry handling, assembles a scorecard, compares it with a compatible baseline, retains the run, and optionally promotes it as a future baseline.

- Pinned suite: Provides the pinned evaluation suite at the start of the run. [In region "1 · Pinned run," an eval/flask icon labeled "Pinned suite" is the first node and has an outgoing arrow labeled "pins."]
- Immutable scenario versions: Holds the immutable versions of the scenarios selected by the pinned suite. [A multiple-documents icon labeled "Immutable scenario versions" receives the "pins" arrow from "Pinned suite."]
- Run fingerprint: Represents the run fingerprint derived after the immutable scenario versions and supplied to bounded execution. [A config/gear icon labeled "Run fingerprint" receives an arrow from "Immutable scenario versions" and has an outgoing arrow to "Bounded scheduler."]

- Worker pool: Executes distributed scenario work, sends scenario steps to the isolated SUT, produces execution artifacts, and is the visible source of execution-failure branches. [An agent icon labeled "Worker pool" receives "bounded fan-out," sends "scenario steps" toward "Isolated SUT," connects toward "Transcript + artifact" on an edge labeled "retry," and has downward branches to the two fault nodes.]
- Isolated SUT: Receives scenario steps as the isolated system under test. [A server icon labeled "Isolated SUT" receives the arrow labeled "scenario steps" from "Worker pool."]
- Transcript + artifact: Stores the transcript and artifact associated with an execution and supplies the completed-scenario grading flow. [A multiple-documents icon labeled "Transcript + artifact" receives a teal arrow and originates the purple route labeled "completed scenario" to the grading region.]
- Infrastructure fault: Represents an infrastructure-failure outcome from bounded execution. [An orange event/lightning icon labeled "Infrastructure fault" is reached by a downward orange arrow from the worker-pool branch.]

- Globally bounded graders: Receives completed scenarios for globally bounded grading and participates in producing criterion verdicts. [In region "3 · Evidence-backed grading," an agent icon labeled "Globally bounded graders" receives the purple "completed scenario" arrow and is connected by a purple route to "Evidence-backed verdicts."]
- Artifact-only grader: Grades only the artifact and sends a blind score to the verdict artifact. [A judge/scales icon labeled "Artifact-only grader" points to "Evidence-backed verdicts" on a magenta arrow labeled "blind score."]
- Evidence-backed verdicts: Collects criterion verdict output and sends it for evidence validation. [A document icon labeled "Evidence-backed verdicts" receives grading arrows and has a downward red route labeled "validate evidence" into the evidence guardrail.]
- Evidence required: Acts as the evidence-validation guardrail, routing invalid results to retry, valid verdicts to scorecard assembly, and failed retries to a flag. - Flag after retry: Represents the failure outcome when the evidence-validation retry fails. [An orange event/lightning icon labeled "Flag after retry" receives the dashed arrow labeled "retry fails."]
- Merge valid verdicts: Combines valid verdicts into the run scorecard. [In region "4 · Assemble scorecard," a predefined-process shape labeled "Merge valid verdicts" receives the purple "valid verdicts" route and points to "Run scorecard."]
- Run scorecard: Stores the assembled scorecard and supplies it to compatible comparison. [A document icon labeled "Run scorecard" receives the arrow from "Merge valid verdicts" and has a blue route entering the comparison decision.]
- Movement threshold: Provides threshold configuration used to narrate crossings in the comparison output. [A config/gear icon labeled "Movement threshold" sends a blue route labeled "narrate crossings" to "Threshold movements."]
- Chosen baseline: Provides the selected baseline to the fingerprint-compatibility comparison. [In region "5 · Compatible comparison," a document icon labeled "Chosen baseline" has a blue arrow entering the decision diamond.]
- Fingerprints match?: Tests whether the run scorecard and chosen baseline have matching fingerprints. [A decision diamond labeled "Fingerprints match?" receives blue inputs from the run-scorecard route and "Chosen baseline"; its visible outgoing branch is labeled "match."]
- Threshold movements: Records threshold movements following a successful fingerprint match and receives movement-crossing narration. [A document icon labeled "Threshold movements" receives the decision branch labeled "match" and the blue route labeled "narrate crossings," then connects to the retention flow.]
- Artifacts, transcripts & verdicts: Archives retained run materials, including artifacts, transcripts, and verdicts. [In region "6 · Retention & promotion," an archive icon labeled "Artifacts, transcripts & verdicts" receives the gray arrow labeled "retain run."]
- Promote run: Provides the human review step for deciding promotion of the retained run. [A human icon labeled "Promote run" receives an orange arrow labeled "review" and sends an arrow labeled "promote."]
- Future baseline: Stores the promoted run as a future baseline. [A document icon labeled "Future baseline" receives the orange arrow labeled "promote" from "Promote run."]
