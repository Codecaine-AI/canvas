# SF blind system reconstruction

## SYSTEM PURPOSE
Operate long-lived agent sessions through a shared control plane: authenticate and place sessions, run model/tool turns, coordinate concurrent child work under shared quotas, persist replayable event history and immutable checkpoints, and release, rescue, resume, fork, or collect sessions while preserving continuity.

## FAILURE PATHS
- Heartbeat loss: "Heartbeat loss / Reclaim capacity + rescue" → "Re-place on available host / Rehydrate latest snapshot" → Use "latest snapshot" → "continue" back to the runner → Capacity is reclaimed, the session is rescued on an available host, and execution continues from the latest snapshot. [Explicit lifecycle boxes and directed heartbeat-loss, latest-snapshot, and continue routes.]
- Interrupt or stop: Active runner → "interrupt / stop" → "Idle / suspend / interrupt" → "Safe checkpoint + release" → The model stream is stopped, tools are abandoned where possible, uncertain outcomes are recorded, and a checkpoint is taken before release. [Orange edge labeled "interrupt / stop" enters the safe-release box; adjacent note states "Stop model stream; abandon tools where possible. Record uncertain outcomes. Checkpoint before release."]
- Tree-wide token, time, tool-call, or concurrency exhaustion: Aggregate limits across tree and workspace are exhausted → Session pauses → The session pauses for a user decision. [Session-tree note states "Tokens, time, tool calls and concurrency aggregate across tree + workspace" and "Exhaustion → pause for user decision."]
- Cancellation or failure within the session tree: Cancellation or failure occurs → It propagates through the tree → A reaper handles orphan children → Orphan child work is killed. [Session-tree note explicitly states "Cancel / failure propagates; reaper kills orphan children."]
- Turn or token ceiling is reached: Execution reaches a turn/token ceiling → Session pauses → Work waits for a user decision. [Rolling-release note states "Finish exits; turn/token ceilings pause for user decision."]
- Old host rejects placement during a rolling release: Old host rejects placement → Work drains via completion, suspension, or safe checkpoint → Replacement occurs → The placement moves only after completion, suspension, or a safe checkpoint. [Lifecycle note states "Rolling release. Old hosts reject placements. Drain via completion, suspension or safe checkpoint before replacement."]

## CONSTRAINTS & BOUNDARIES
- Capacity, residency, and isolation are scheduler concerns during placement. [Scheduler box reads "capacity / Residency + isolation".]
- Workspace and quota controls are applied at admission. [API box reads "authenticate / Workspace + quotas".]
- Token, time, tool-call, and concurrency use aggregates across the entire session tree and workspace. [Tree-wide enforcement note states "Tokens, time, tool calls and concurrency aggregate across tree + workspace."]
- Children consume the parent's allowance, and held children continue to count. [Tree-wide enforcement note states "Children draw from parent allowance; held children still count."]
- Parent orchestration assigns scoped budgets and children operate with scoped contexts. [Parent box says "Allocate scoped budgets"; Child A and Child B boxes each say "scoped context".]
- Tool execution uses idempotency keys. [Tool execution box is labeled "Execute tools / Idempotency keys".]
- Live-output replay begins after the client's last acknowledgement. [Output box states "Replay after last ACK".]
- Every completed turn is checkpointed as a content-addressed snapshot. [Blue "completed turn" edge enters the box "Checkpoint each turn / Content-addressed snapshot".]
- Snapshots are immutable and include conversation, tools, and files. [Durability note states "Immutable snapshots Conversation, tools, files."]
- Each snapshot names its prior snapshot as parent, and unchanged content is deduplicated. [Durability note states "Parent = prior snapshot. Unchanged content deduplicates."]
- Audit records cover requests, responses, tools and results, checkpoint references, budget decisions, and lifecycle events. [Audit note explicitly lists those items.]
- Audit information supports forensics, replay, metering, and per-session cost accounting. [Audit note is headed "Audit → metering" and states the records "support forensics, replay and per-session costs."]
- On interruption, stop the model stream, abandon tools where possible, record uncertain outcomes, and checkpoint before release. [Lifecycle note states those four requirements verbatim.]
- Recovery replays no more than one turn from the last checkpoint. [Lifecycle route is labeled "last checkpoint · ≤1 turn replay".]
- During rolling release, old hosts reject placements and drain before replacement through completion, suspension, or safe checkpoint. [Rolling-release note explicitly states this behavior.]
- A disconnect does not equal cancellation; work continues. [Rolling-release note states "Disconnect ≠ cancel: work continues."]
- Normal finish exits, while turn or token ceilings pause for user decision. [Rolling-release note states "Finish exits; turn/token ceilings pause for user decision."]
- Deleting a session makes unreferenced snapshots eligible for collection. [Reachability-retention note states "Delete session → unreferenced snapshots eligible for collection."]
- Fork references keep shared ancestors alive. [Reachability-retention note states "Fork references keep shared ancestors alive."]
- Each fork writes its own future without copying shared content. [Reachability-retention note states "each branch writes its own future without copying shared content."]
