# SF blind system reconstruction

## SYSTEM PURPOSE
Orchestrate reproducible evaluation runs from an immutable pinned suite: execute ordered scenarios in an isolated non-production system with bounded workers, grade each completion concurrently under a global limit, require evidence for valid verdicts, compare only fingerprint-compatible results with a chosen baseline, and retain artifacts, transcripts, typed faults, and verdicts for audit and disputed-score review.

## COMPONENTS
- 1 · Immutable run contract: Defines the frozen, versioned input contract for a run. [Blue region titled "1 · Immutable run contract" contains "Pinned suite" and a note describing a frozen contract and fingerprint.]
- Pinned suite: Provides the suite used to create a pinned run. [Document icon labeled "Pinned suite" has a right-pointing edge labeled "pinned run" to the Scheduler.]
- Frozen contract: Prevents in-place wording changes and identifies the versioned material included in the run fingerprint. [Note reads: "Frozen contract / Wording changes → new scenario versions; never edit in place. / Fingerprint: revision, configuration, prompt versions, rubric versions."]

[Orchestrator icon labeled "Scheduler" receives "pinned run" and has a rightward edge labeled "fan out" to the worker pool; an orange dashed retry path is labeled "retry infrastructure only".]

- 3 · Concurrent grading · global limit G: Grades each completed scenario immediately, using multiple independent graders while enforcing global grading limit G. [Pink region title is "3 · Concurrent grading · global limit G"; the green coordination icon reads "Grade immediately / Global limit G".]

- 4 · Compatible comparison: Assembles valid verdicts, checks fingerprint compatibility, compares compatible runs with a chosen baseline, and supports promotion to a future baseline. - Same fingerprint?: Determines whether the assembled result and chosen baseline have matching fingerprints before comparison. [Decision diamond reads "Same fingerprint?"; its green "yes" branch goes to comparison and its red "no" branch goes to "Incompatible / Do not compare".]
- Incompatible: Stops comparison when fingerprints are not the same. [Predefined-process box reads "Incompatible / Do not compare" and is reached by the red "no" branch from "Same fingerprint?".]
- Compare with baseline: Compares a fingerprint-compatible scorecard with the chosen baseline and narrates score differences meeting the threshold. [Predefined-process box reads "Compare with baseline / Narrate |Δ| ≥ threshold" and is reached by the green "yes" branch from "Same fingerprint?".]

- Scenario steps are ordered. [Worker box reads "Ordered scenario steps".]

- Only infrastructure failures are retried by the execution retry loop. [Orange dashed loop is labeled "retry infrastructure only".]

- Grading is immediate and subject to global limit G. [Region title says "Concurrent grading · global limit G" and the coordination node says "Grade immediately / Global limit G".]
