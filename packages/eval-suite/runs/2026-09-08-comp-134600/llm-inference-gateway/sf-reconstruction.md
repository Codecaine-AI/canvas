# SF blind system reconstruction

## SYSTEM PURPOSE
An "llm-inference-gateway" that admits and prepares requests, uses a deterministic response cache, ranks eligible hosted or self-hosted backends, streams successful responses, retries eligible failures that occur before the first token, meters usage and spend, protects capacity with circuit breakers, and sends samples to a shadow evaluation backend without affecting the client response.

## FAILURE PATHS
- The admission controller determines that the request is over limit.: Admission controller → over limit → Deadline-aware queue → The work waits for a slot before its deadline or proceeds to deadline-expiry rejection. [The admission controller has a downward route labeled "over limit" to "Deadline-aware queue," which has routes labeled "slot before deadline" and "deadline expired."]
- A queued request's deadline expires before a slot is obtained.: Deadline-aware queue → deadline expired → Reject explicitly → The caller must retry; the system must never serve the request late. [The red path is labeled "deadline expired," and the destination states "Caller must retry · never serve late."]
- A backend response or error produces a failure before the first token.: Hosted providers or Self-hosted pool → response / error → Attempt outcome → pre-token failure → Classify failure → The failure is classified as retryable or otherwise. [Both capacity paths feed "Attempt outcome — Before first token" through lines labeled "response / error"; a red line labeled "pre-token failure" leads to "Classify failure — Retryable?"]
- A pre-token failure is classified as retryable.: Classify failure → retryable → Next backend in tier → reselect eligible fallback → Tier router → Another eligible backend in the same tier is selected, using a fresh deadline and the same idempotency key. [The orange branch is labeled "retryable" and reaches a box stating "Next backend in tier — Fresh deadline · same idempotency key"; the orange back-edge is labeled "reselect eligible fallback" and points into the tier router.]
- A pre-token failure is not retryable, or eligible retries are exhausted.: Classify failure → otherwise → Return error immediately → An error is returned immediately. [The red branch labeled "otherwise" reaches the box "Return error immediately — Non-retryable / exhausted."]
- A failure occurs after tokens have already been received or streaming has begun.: Stream tokens to caller → Complete or visibly fail → Received tokens are preserved and no retry is performed. [The completion box downstream of streaming states "Preserve received tokens · no retry."]
- Sustained backend errors or timeouts occur.: Circuit breakers → Open on sustained errors / timeouts → drain to healthy → Tier router → The circuit opens and routing is directed toward healthy capacity. [The circuit-breaker box explicitly says "Open on sustained errors / timeouts," and its dashed orange routing relationship is labeled "drain to healthy."]
- An opened or unhealthy circuit is tested and the probe reports healthy.: Circuit breakers → test / recover → Trickle shadow probes → Healthy → close circuit → The circuit is closed. [The dashed orange relationship is labeled "test / recover," and the probe box explicitly says "Healthy → close circuit."]
- Spend control cannot remain within the spend ceiling after selecting the cheapest capable option.: Spend ceiling → 1 Cheapest capable → 2 Reject new work → spend gate → Admission path → New work is rejected. [The spend-control box explicitly orders "1 Cheapest capable · 2 Reject new work" and connects to admission through the dashed blue "spend gate" route.]
