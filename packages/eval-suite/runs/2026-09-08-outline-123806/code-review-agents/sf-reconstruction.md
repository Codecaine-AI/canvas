# SF blind system reconstruction

## SYSTEM PURPOSE
Multi-agent automated code review of a pull request: intake and filter the change, build and dispatch shared review context to concurrent specialist reviewers, merge and verify findings, publish inline comments and a verdict, and use replies or disagreements to calibrate later confidence thresholds.

## FAILURE PATHS
- A force-push or new commit changes the repository head during an in-flight review.: Head monitor: cancel / restart → Cancel the in-flight review → Discard partial work → Never publish against the old diff → Cancel; restart new head → Restart intake on the new head → The old review is abandoned without publication and intake restarts against the new head. [The lifecycle note gives the trigger and full outcome, and the red dashed arrow labeled “Cancel; restart new head” points to the intake region.]
- A per-review read-only tool call budget is exhausted.: Read-only tools · call budget → Call-budget exhaustion → Stop further tool use → Return available findings immediately → The review returns whatever findings are already available rather than waiting for more tool calls. [The read-only-tools note states: “Per-review call budget: on exhaustion, return available findings immediately.”]
- The daily repository budget is exceeded.: Telemetry / daily budget → Over daily budget: 2 reviewers → Intake limits subsequent runs → Run only Correctness and Security review → Subsequent runs use two reviewers—Correctness and Security—instead of all five specialist reviewers. [The telemetry note states that exceeding the daily repository budget limits subsequent runs to correctness and security only; the orange dashed edge is labeled “Over daily budget: 2 reviewers.”]
- A finding has low confidence.: Merge & deduplicate → Reconcile severities → Identify low confidence → Withhold the finding → The low-confidence finding does not proceed as a surviving finding for publication. [The merge-and-verify note explicitly says: “withhold low confidence.”]
- A finding location no longer exists on the current head.: Check current head → Determine that the location no longer exists → Drop the location/finding → The stale-location finding is removed before publication. [The merge-and-verify note says: “Check current head; drop locations that no longer exist.”]
- A high-severity finding cannot be verified in source.: Verify high severity in source → Verification does not establish the finding → Demote the finding → Do not post it → The unverified high-severity finding is demoted and excluded from publication. [The merge-and-verify note says: “Unverified high-severity findings are demoted, not posted.”]
- A published finding is resolved as wrong through replies or human disagreement.: Inline comments + verdict → Replies / disagreements → Calibration thresholds → Record the finding as resolved wrong → Adjust later confidence thresholds by finding class → Future confidence thresholds are recalibrated for the relevant finding class. [The publish-and-calibrate note says that replies and human disagreements feed calibration and that findings resolved as wrong adjust later confidence thresholds by finding class.]
