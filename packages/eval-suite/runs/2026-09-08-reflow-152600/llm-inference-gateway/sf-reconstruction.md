# SF blind system reconstruction

## SYSTEM PURPOSE
An LLM inference gateway that admits tenant requests, assembles prompts, checks a response cache, selects eligible backend capacity by tier, executes attempts against hosted or self-hosted providers, streams tokens, performs bounded pre-token recovery, protects capacity and spend, and emits billing, audit, and isolated-evaluation data.

## FAILURE PATHS
- A queued admission request reaches its deadline before obtaining a slot.: Admission controller → Deadline queue → deadline expired → Reject to caller → The caller is told to retry; the system never serves the request late. [The queue path is labeled “excess ↔ slot before deadline”; its outgoing arrow is “deadline expired”; the destination says “Retry; never serve late.”]
- Attempt executor reports a backend failure after tokens have been emitted.: Attempt executor → backend failure → Tokens emitted? = yes → Visibly fail stream → Preserve emitted tokens and perform no retry. [The red “backend failure” route enters Tokens emitted? and the red “yes” route ends at “Visibly fail stream / Preserve emitted tokens · no retry.”]
- Attempt executor reports a backend failure before tokens have been emitted, and the failure is classified as retryable.: Attempt executor → backend failure → Tokens emitted? = no → Classify pre-token failure / Retryable? = yes → Next backend in tier → reselect eligible capacity → Tier router → Attempt executor → Retry using the next backend in the tier, with a fresh deadline and the same key and request ID. [The “no” and “yes” branch labels lead to “Next backend in tier / Fresh deadline · same key + ID,” and its back-edge is labeled “reselect eligible capacity.”]
- Attempt executor reports a backend failure before tokens have been emitted, and the failure is classified as non-retryable.: Attempt executor → backend failure → Tokens emitted? = no → Classify pre-token failure / Retryable? = no → Return error immediately → An error is returned immediately as a non-retryable failure. [The classification box’s red “no” route points to “Return error immediately / Non-retryable failure.”]
- Sustained errors or timeouts occur for capacity.: Circuit breakers → open circuit → exclude open circuits → Tier router → Open circuits are excluded from eligible routing until probing finds them healthy and closes them. [The box states “Open on sustained errors / timeouts”; the dashed router input is labeled “exclude open circuits”; the probe label states “open → probe; healthy → close.”]
- The spend ceiling reaches its second protection action.: Spend ceiling → 2 · reject new work → Admission controller → New work is rejected at admission. [The Spend ceiling box lists “2 Reject new,” and a red dashed arrow labeled “2 · reject new work” points into Admission controller.]
