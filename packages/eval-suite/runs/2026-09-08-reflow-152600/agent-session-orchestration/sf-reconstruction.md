# SF blind system reconstruction

## SYSTEM PURPOSE
Orchestrate long-lived agent sessions across admission, host placement, model/tool turn execution, live output, durable audit and checkpoint recovery, coordinated shutdown, crash replacement, and concurrent parent/child session allowances.

- Client: Human participant that opens a session, receives live or replayed output, and can be asked for a decision when allowances are exhausted. - Tool executor: Executes permitted tool calls and returns results to the turn orchestrator. [Tool icon labeled "Tool executor" connected to Turn orchestrator by the edge "Calls ⇄ results"; the Turn loop note says permitted tools are assembled and results are appended.]

- Quiesce & checkpoint: Quiesces active work and creates a durable checkpoint during lifecycle shutdown. [Process rectangle labeled "Quiesce & checkpoint" in "Lifecycle & coordinated shutdown".]
- Release runner: Releases the runner after a durable snapshot has been made. [Process rectangle labeled "Release runner" reached from "Quiesce & checkpoint" by the arrow labeled "Snapshot durable".]

- Admission & placement policy: Authenticates the user, resolves workspace and quotas, and selects capacity subject to residency and isolation constraints. ## FAILURE PATHS
- Runner host crash detected by Heartbeat monitor.: Heartbeat monitor → "Crash: replace host" → Rehydrate latest snapshot → "Rehydrated: continue turns" → Turn orchestrator → The latest snapshot is restored on a replacement/selected host and turn execution continues. [The lifecycle region shows the monitor-to-rehydration crash arrow, while Snapshot chain feeds rehydration and a teal arrow returns to Turn orchestrator.]
- Idle, suspend, cancel, deploy drain, interrupt, or done lifecycle condition.: Stop model streaming → Abandon tools where possible → Record uncertain outcomes → Quiesce & checkpoint → "Snapshot durable" → Release runner → A durable checkpoint is created before the runner is released; old hosts reject new placements and drain before replacement. [Orange lifecycle route "Done / idle / suspend / interrupt / drain", the two process boxes joined by "Snapshot durable", and the "Safe interruption" note.]
- Client disconnect during live output.: Client disconnects → Active work continues → Output and audit events continue to Event log → Replay after last ACK → Client reattaches → Disconnect does not stop work; persisted output can be replayed from after the last acknowledgment before reattachment. [Top label "Live output • disconnect does not stop work", Event log write route, and blue return route "Replay after last ACK; then reattach".]
- Tree or workspace allowances are exhausted.: Child sessions report "Tree + workspace usage" → Aggregate allowances → "Exhausted: pause, ask user" → User decision → Execution pauses and a human decision is requested. [Explicit labeled arrows in the concurrent-session region.]
- Parent session is gone.: "Parent gone" → Reap orphan children → "Terminate survivors" → Child sessions → Surviving orphan child sessions are terminated. [Gray parent-gone route into the reaping process and red termination route ending at Child sessions.]
- Cancellation or failure within the concurrent session tree.: Cancellation or failure occurs → Propagation across the session tree → Held children remain accounted for → Results return through the parent where applicable → Cancellation and failure propagate tree-wide rather than remaining isolated to one child. [The "Tree-wide control" note states: "Held children remain accounted for. Cancellation and failure propagate; results return through the parent."]
- Recovery after an interrupted in-flight turn.: Load durable audit/checkpoint state → Replay at most the in-flight turn → Reuse idempotency keys for external writes → Recovery is bounded to at most one in-flight turn and repeated external writes use the same idempotency keys. [The "Durable audit & recovery" note explicitly states the replay bound and idempotency-key reuse.]

- Admission must authenticate the user and resolve workspace and quotas. [Admission & placement note.]
- Capacity selection must obey residency and isolation constraints. [Admission & placement note: "Select capacity within residency and isolation constraints."]
- The turn loop stops when done or when a turn/token ceiling is reached. [Turn loop note.]
- External writes carry idempotency keys, and recovery reuses those keys. [Turn loop and Durable audit & recovery notes.]
- A completed turn or safe stop is checkpointed. [Route labeled "Completed turn / safe stop: checkpoint" into Snapshot chain.]
- Runner release occurs only after the snapshot is durable. [Quiesce & checkpoint → "Snapshot durable" → Release runner.]
- During safe interruption, model streaming stops and tools are abandoned only where possible; uncertain outcomes must be recorded before checkpointing. [Safe interruption note.]

- Checkpoints are immutable and include conversation, tool results, and workspace files. [Immutable checkpoints note.]

- Tokens, wall-clock time, tool calls, and concurrent sessions count against both tree and workspace limits. [Tree-wide control note.]
- Held child sessions remain accounted for. [Tree-wide control note.]
- Cancellation and failure propagate across the session tree. [Tree-wide control note.]
