# SF blind system reconstruction

## SYSTEM PURPOSE
A sandboxed tool fleet that admits agent requests under tenant quotas, places them onto warm or newly provisioned instances, grants disposable fixed-term leases, controls tool execution within each lease, manages fleet supply and unhealthy hosts, retires instances without recycling them, and exposes operational telemetry.

- Agent: Submits an image-and-class request for admission. [Agent icon labeled "Agent" has an outgoing arrow labeled "Image + class" to "Tenant quota admission".]
- Tenant quota admission: Checks admission against tenant quota and either permits placement or routes excess demand through fair waiting. [Process labeled "Tenant quota admission" has an outgoing route labeled "Quota available" and a loop labeled "Exceeded → wait / ← fair retry".]

- Placement: claim warm match: Attempts to claim a matching warm instance. [Process labeled "Placement: claim warm match" routes a "Hit: immediate" to the warm pool and a "Miss" downward to host selection.]

## FAILURE PATHS
- Tenant quota is exceeded.: Tenant quota admission → Fair wait → Fair retry to Tenant quota admission → The excess request waits fairly and retries admission rather than proceeding immediately. [The admission loop is labeled "Exceeded → wait / ← fair retry"; the fair-admission note says "Excess requests wait fairly".]
- Warm placement returns "Miss".: Placement: claim warm match → Select healthy host + capacity → Provisioning: await boot → Ready: warm pool → A cold start is performed and, after boot completion, the instance becomes ready. [The branch labels are "Miss", "Cold start", and "Boot complete" on the ordered arrows.]
- Repeated boot failures.: Quarantine failing host → Exclude host after repeated boot failures → Select healthy host + capacity → The failing host is excluded from host selection. [Red dashed upward arrow from "Quarantine failing host" into host selection is labeled "Exclude host after repeated boot failures".]
- Lease renewals stop or maximum age is reached.: Leased: fixed term + heartbeats → Reclaimer: revoke lease → Destroyed: erase local state → The lease is revoked and the instance is destroyed without recycling. [The arrows are labeled "Renewals stop / max age" and "Never recycle".]
- Unleased warm supply reaches maximum age.: Ready: warm pool → Reclaimer: revoke lease → Destroyed: erase local state → The unleased instance is reclaimed and destroyed without recycling. [Dashed path labeled "Max age: unleased supply" reaches the reclaimer, followed by "Never recycle" to destruction.]
- An image is retired while an instance is leased.: Leased: fixed term + heartbeats → Draining: no new leases → Destroyed: erase local state → No new leases are accepted; active leases finish before destruction. [Dashed arrow labeled "Image retired" enters draining, and the downward route to destruction is labeled "Active leases finished".]
- A tool or code call exceeds its deadline.: Execute tool / code → Kill call: report timeout → Agent · active lease → The call is killed and reported to the agent as a timeout, not as a tool error. [The two route labels are "Deadline exceeded" and "Timeout, not tool error".]

## CONSTRAINTS & BOUNDARIES
- Admission is fair across concurrent environments and aggregate runtime per tenant. [Yellow note titled "Fair admission" states: "Concurrent environments + aggregate runtime per tenant."]
- Excess requests must wait fairly. [The fair-admission note states "Excess requests wait fairly", and the diagram includes the "Fair wait" loop.]
- Reserved capacity cannot be borrowed. [The fair-admission note explicitly states "no borrowing reserved capacity."]
- Leases have a fixed term and use heartbeats. [Active lease process is labeled "Leased: fixed term + heartbeats".]
- Lease instances are disposable and never recycled. [Lease region title says "disposable, never recycled", and the reclaimer-to-destroyed route is labeled "Never recycle".]
- Used instances are retired after their lease ends. ["Idle: lease ended" routes downward by "Retire used instance" to draining.]
- Draining instances accept no new leases. [The process is explicitly labeled "Draining: no new leases".]
- Local state is erased when an instance is destroyed. [Terminal lifecycle process is labeled "Destroyed: erase local state".]
- An image release marks older instances as draining while live work continues until active leases end. [Yellow "Image release" note states "Mark older instances draining; live work continues until active leases end."]
- An absolute maximum age applies to every environment, including unleased supply. [The image-release note states "Absolute max age" and "Applies to every environment, including unleased supply."]
- Each call is limited by time, RAM, and CPU. [Process labeled "Per-call limits: time / RAM / CPU" is connected to execution by "Enforce".]
- Network egress is allowlist-only. [Execution routes through "Network policy" to "Egress proxy: allowlist only".]
- Call output is capped. [Agent/execution edge label includes "← capped output".]
- Deadline expiration is reported as a timeout rather than a tool error. [Kill-call output route is explicitly labeled "Timeout, not tool error".]
- Fleet telemetry includes boot latency, lease reclamations, tool timeouts, and escape-attempt signals. [The "Fleet signals" note lists all four items.]
