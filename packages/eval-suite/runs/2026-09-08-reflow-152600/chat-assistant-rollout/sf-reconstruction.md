# SF blind system reconstruction

## SYSTEM PURPOSE
A support assistant that provides guarded, context-aware customer-chat replies using conversation history, durable profile facts, retrieved support articles, and account actions; hands conversations to a support agent when requested or repeatedly triggered; distills durable memory after conversations; and stages versioned challenger variants through live monitoring, judged experiments, human promotion, rollback, or removal.

- Customer Web / mobile chat: Provides the customer conversation turn to the live assistant. [A message-surface icon labeled "Customer Web / mobile chat" begins the live flow and connects through an edge labeled "Turn".]
- Input safety: Guards incoming customer turns and either allows processing or participates in the handoff route. [A guardrail icon labeled "Input safety" receives the customer turn; a gray outgoing edge is labeled "Allowed", while a red route above it is associated with repeated triggers/customer-request handoff.]
- Assemble turn context: Combines the allowed turn with profile facts, conversation history, and relevant articles into context for reply generation. - Long-term profile: Stores durable profile facts across turns and supplies those facts during live context assembly. [A memory-store icon labeled "Long-term profile" has a downward connection labeled "Profile facts" toward context assembly and a blue incoming route from durable-fact distillation.]
- Live transcript: Stores the current conversation, supplies conversation-so-far context, and initiates post-conversation distillation when the conversation ends. [A memory-store icon labeled "Live transcript" connects upward via "Conversation so far" to context assembly and downward via "Conversation ended" to "Distill durable facts".]
- Support corpus: Acts as the reference corpus searched for support information. [A knowledge icon labeled "Support corpus" connects leftward to "Search help center" through an arrow labeled "Search corpus".]
- Search help center: Searches the support corpus and supplies relevant articles for the assembled turn context. [A search icon labeled "Search help center" receives the left-pointing "Search corpus" edge from the support corpus and has a route labeled "Relevant articles" toward context assembly.]
- Generate reply / action: Uses assembled context to draft a reply or invoke an account-related action. [A model icon labeled "Generate reply / action" receives "Assembled context", emits "Draft reply" toward output safety, and is connected to billing/account actions by an "Action / result" route.]

- Managed secrets vault: Provides a secret for each billing/account action invocation. [A key icon labeled "Managed secrets vault" points left toward billing/account actions through an edge labeled "Per-call secret".]
- Output safety: Guards the drafted reply before it is sent and routes either a passing reply or safe fallback. [A guardrail icon labeled "Output safety" receives the "Draft reply" edge and emits an edge labeled "Pass / safe fallback".]
- Reply to customer: Dispatches the approved reply or safe fallback to the customer. [A send icon labeled "Reply to customer" is the destination of the "Pass / safe fallback" edge.]
- Support agent: Receives handed-off conversations after repeated triggers or a customer request. [A human icon labeled "Support agent" receives a red downward arrow labeled "Repeated triggers / customer request • handoff"; another nearby label reads "Repeated input triggers / requested agent".]
- Distill durable facts: Processes an ended live transcript into durable facts and source-conversation references for the long-term profile. [A model icon labeled "Distill durable facts" receives the transcript edge labeled "Conversation ended" and has a blue route labeled "Upsert facts + source conversation" leading to the long-term profile.]
- Cold history: Archives raw logs after retention expires for compliance recovery rather than live retrieval. [An archive icon labeled "Cold history" receives a downward edge labeled "Retention expired • archive raw log"; the durable-memory note says "Cold history: compliance recovery only; never live retrieval."]
- Quality by variant: Independently observes live quality metrics by variant and triggers immediate challenger removal on regression. [A monitor icon labeled "Quality by variant" receives a dashed route labeled "Live outcomes + safety / handoff events" and has a red route labeled "Any regression: remove challenger now".]
- Versioned variants: Holds the versioned assistant variants used for experiments and traffic assignment. [A gear-shaped node labeled "Versioned variants" sends "Load config" to sampling, receives the red regression-removal route, and is the destination of a blue upward promotion/return route.]
- Sample conversations: Loads variant configuration and splits conversations between champion and challenger. [An orchestrator icon labeled "Sample conversations" receives "Load config" and branches via "Most traffic" to Champion and "Small sample" to Challenger.]
- Champion: Handles most experiment traffic and supplies completed champion chats for judging. [A gear-shaped node labeled "Champion" receives the "Most traffic" branch and sends a route labeled "Completed champion chats" to the judge panel.]
- Challenger: Handles a small experimental sample and supplies challenger results for judging. [A gear-shaped node labeled "Challenger" receives the "Small sample" branch and sends a route labeled "Challenger results" to the judge panel.]
- Judge panel: Compares champion chats and challenger results and accumulates verdicts. [A judge icon labeled "Judge panel" receives both experiment branches and sends a downward edge labeled "Accumulate verdicts".]
- Experiment report: Records accumulated judge verdicts for review. [A document icon labeled "Experiment report" receives the downward "Accumulate verdicts" edge and connects toward product-owner review through "Clears bar • review".]
- Product owner: Reviews an experiment that clears the bar and either approves a champion swap while retaining the old version or rejects it and keeps the champion. [A human icon labeled "Product owner" receives the "Clears bar • review" route; nearby outgoing routes are labeled "Approve: swap champion; retain old", "Retain old ↔ one-step rollback", and "Reject".]
- Previous champion: Retains the prior champion as the rollback target. [A gear-shaped node labeled "Previous champion" is reached by a blue downward arrow beside the label "Retain old ↔ one-step rollback".]
- Keep champion: Stops the promotion procedure with the current champion retained after rejection. [An octagonal stop node labeled "Keep champion" receives a red arrow labeled "Reject" from the product-owner side.]

[The red handoff path is labeled both "Repeated input triggers / requested agent" and "Repeated triggers / customer request • handoff" and ends at Support agent.]

[The independent-checks note says "Per variant; pull on any regression", and the red route into Versioned variants is labeled "Any regression: remove challenger now".]
