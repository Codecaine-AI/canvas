# SF blind system reconstruction

## SYSTEM PURPOSE
A retrieval corpus pipeline that ingests scheduled source changes with ACLs, isolates bad inputs, detects new/changed content, chunks and embeds it, publishes version-consistent vector/text/keyword data, retrieves and permission-filters evidence for answers, captures coverage feedback, and rebuilds embedding generations with atomic promotion and rollback support.

- 3 · Permission-aware retrieval & answers: Region containing query rewriting, parallel vector and keyword retrieval, reranking, ACL filtering, answer sufficiency handling, citations, and feedback. [Lower-left region is explicitly titled “3 · Permission-aware retrieval & answers.”]

## FAILURE PATHS
- Extraction or normalization cannot parse an input.: Extract & normalize → unparseable; batch continues → Quarantine + failure context → The bad input and failure context are quarantined while the batch continues. [A red downward arrow from “Extract & normalize” is labeled “unparseable; batch continues” and terminates at “Quarantine + failure context.”]
- An embedding batch fails.: Rate-limited embedding batches → failure / retry → Workers: bounded retry → Dead-letter: inputs + attempts → The work is retried within a bound and ultimately dead-lettered with its inputs and attempts if it does not recover. [A red route labeled “failure / retry” connects embedding batches to “Workers: bounded retry,” followed by a red downward arrow to “Dead-letter: inputs + attempts.”]
- A publication operation produces a partial write.: Publish only if 3 versions match → partial write → Unavailable: repair or roll back → The publication is unavailable and must be repaired or rolled back. [A red route labeled “partial write” runs from the publication gate area to “Unavailable: repair or roll back.”]
- Authorized context is not sufficient or does not have a strong score.: Enough context + strong score? → no → I don't know → unanswered questions → Feedback → coverage gaps → The system returns “I don't know” and records the unanswered question as a coverage gap. [The “no” branch enters “I don't know,” whose downstream route labeled “unanswered questions” enters “Feedback → coverage gaps.”]
