# SF blind system reconstruction

## SYSTEM PURPOSE
A backpressured, tenant-aware data pipeline that authenticates and schema-checks producer records, buffers them in a partitioned durable log, processes them in partition order, preserves failed records for quarantine or repair, writes idempotent batches to an analytics warehouse, serves tenant queries with caching, supports replay after logic changes, and applies operational throttling as downstream capacity degrades.

## FAILURE PATHS
- A record has an unknown schema during schema-and-record handling.: Schema + record... → Unknown-schema quarantine → Review / repair / replay → Repair/replay route → The record is quarantined rather than silently accepted; it can be reviewed, repaired, and replayed while tenant, event, and receipt identity is preserved. [An orange path leads from schema handling to “Unknown-schema quarantine”; dashed orange routing descends toward “Review / repair / replay”. The identity note requires IDs to be preserved through quarantine, repair, and replay.]
- Schema or record validation results in rejection.: Schema + record... → Reject + explicit reason → The record is rejected with an explicit reason. [A red failure path leaves the schema/record area and points to the red box labeled “Reject + explicit reason”.]
- Transform processing produces an error.: Transfor m... → Dead-letter stream → Review / repair / replay → Repair route toward downstream processing/loading → The error and original identity are retained for review and repair; repaired data can be replayed without changing tenant/event identity. [A downward orange arrow reaches “Dead-letter stream / Error + original identity”; a dashed orange route connects the dead-letter area to “Review / repair / replay”, which says “Preserve tenant + event ID”.]
- Transform logic changes.: Low-cost object storage → logic-change replay → Review / repair / replay → Warehouse loading path → Stored successful data is replayed, and warehouse writes remain idempotent. [The object-storage box says “Replay source”; its outgoing dashed blue flow is labeled “logic-change replay”. - Warehouse slowdown.: Warehouse slowdown → Warehouse loading queue expands → Transform consumption is reduced → Durable-log backlog approaches retention safety limit → Ingest gateway throttles → Ingest returns explicit throttling responses before the durable-log retention safety limit is exceeded. [The ordered sequence is printed in the “Backpressure ladder”; the dashed red line labeled “retention safety limit · throttle” terminates at the ingest gateway.]
- Operational metrics cross configured thresholds.: Pipeline stage metrics → Stage telemetry → thresholds → Operational alerts → An operational alert is generated. [The telemetry box lists monitored conditions, and its outgoing connector labeled “thresholds” leads to the lightning icon labeled “Operational alerts”.]

## CONSTRAINTS & BOUNDARIES
- Tenant, event, and receipt IDs are attached once and preserved through quarantine, repair, replay, and downstream deduplication. [Explicitly stated in the “**Identity invariant**” note.]
- Each partition must be read in order. [The “**Delivery contract**” note says “Read each partition in order”; the reader is named “Partition-ordered reader” and its input is labeled “partition order”.]
- Retries must not change identity. [The “**Delivery contract**” note says “Retry without identity changes”.]
- Downstream writes deduplicate by tenant plus event ID. [The “**Delivery contract**” note says “Downstream writes deduplicate by tenant + event ID”.]
- Warehouse loading uses idempotent batches. [The queue-to-loader flow is labeled “idempotent batch”, and the loader box says “Idempotent batches”.]
- Warehouse writes remain idempotent during reprocessing. [The “**Reprocessing path**” note explicitly says “warehouse writes remain idempotent.”]
- When transform logic changes, low-cost object storage is the replay source. [The “**Reprocessing path**” note explicitly names object storage as the source for replay, and the object-storage box itself says “Replay source”.]
- Ingest must throttle near the durable-log retention safety limit. [The top control path is labeled “retention safety limit · throttle”, and step 3 of the backpressure ladder says ingest returns explicit throttling responses near that limit.]
- Backpressure response is ordered: loading queue expansion, reduced transform consumption, then explicit ingest throttling. [The “**Backpressure ladder**” presents those actions as numbered steps 1, 2, and 3.]
- Transform workers are stateless and perform normalization, redaction, and enrichment. [The worker box is labeled “Stateless transform workers / Normalize · redact · enrich”.]
- Transform failures retain both the error and original identity. [The dead-letter box reads “Error + original identity”.]
