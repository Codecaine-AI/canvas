# Long-lived agent session orchestration

We need a diagram of how our platform runs long-lived AI agent sessions through a shared control plane. A client opens a session at the API tier, which authenticates the user, resolves the workspace and its quotas, and asks the session scheduler for placement. The scheduler selects a runner host with enough capacity while honoring workspace residency and isolation requirements. On that host, the orchestrator repeatedly assembles a model request from system context, conversation history, and the permitted tool surface. It calls the model, receives and executes tool calls, appends their results, and begins the next turn until the agent finishes or reaches its turn or token ceiling.

Turn output streams to the client as it is produced, while the identical stream is committed to a durable event log. A disconnected client does not terminate the work. The session continues, and a returning client reattaches to the live stream after replaying missed events from its last acknowledged position. Every completed turn also creates a durable checkpoint containing conversation state, tool results, and the workspace file state. The checkpoint is a content-addressed snapshot whose parent is the prior snapshot, producing an immutable history that deduplicates unchanged content instead of rewriting a mutable copy.

Idle sessions and sessions suspended on demand release their runners but retain their snapshot chains. Resume may occur on another host, which rehydrates the latest snapshot before continuing. A heartbeat monitor detects crashed runners, returns their capacity to the scheduler, and rescues affected sessions from the last checkpoint. Recovery replays at most the turn that was in flight, so every tool call that can change external state carries an idempotency key in case that call completed before the crash. Cancellation or interruption can also arrive during a turn. The orchestrator stops the model stream, abandons in-flight tool calls where possible, records their uncertain outcome when it cannot confirm termination, and commits a resumable checkpoint before releasing the runner.

An agent may spawn child sessions for independent subtasks. Each child receives scoped context and a budget drawn from its parent's remaining allowance, runs concurrently, and returns its result through the parent orchestrator. Cancellation and failure propagate through the session tree, and a reaper terminates any child that survives after its parent is gone. Quota enforcement therefore aggregates token spend, wall-clock time, tool-call counts, and concurrent sessions across the tree as well as across the workspace. Exhausting an allowance pauses the affected session for a user decision instead of silently truncating its work; held children remain accounted for while the parent waits.

The event log records each request, model response, tool call and result, checkpoint reference, budget decision, and lifecycle transition. It supports forensic reconstruction and replay while feeding usage metering and per-session cost accounting. Snapshot retention follows reachability: deleting a session makes its unreferenced chain eligible for collection, but a snapshot retained by a fork remains alive. Forking from an earlier checkpoint creates a divergent history with its own future checkpoints, without duplicating shared content. Orchestrator deployments must account for sessions that outlive a release, so hosts running the old version stop accepting placements and drain their active sessions through completion, suspension, or a safe checkpoint before replacement. The diagram should make clear how streaming execution, durable state, recovery, branching, quotas, and coordinated shutdown interact throughout a session's lifetime.
