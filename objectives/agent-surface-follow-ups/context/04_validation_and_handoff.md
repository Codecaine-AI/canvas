<validation_and_handoff>
    <validation_ladder>
        - `bun run docs render docs/30-agent-layout/<bundle>`: every doc edit;
          pass = renders without error and the sentence reads correctly on the
          agent surface. Note that a reference span renders as its path, not
          its label — a sentence built around the label will read wrong there.
        - `bun run docs backlinks rescan docs`: any reference change; pass =
          the scan completes and the source/reference counts move as expected.
        - `bun run docs links check docs`: any reference change; pass = no
          stale references.
        - `git diff` block-id review: every rulebook edit; pass = only the
          intended blocks changed and every must-preserve block is byte-
          identical.
        - `bun test packages/canvas-agent`: any F4 code change; pass = 0 fail.
        - Isolated-root smoke run: F4 only; pass = a session started against a
          scratch kernel root writes trace database, manifest, agent state,
          and session directory there and nothing into the default tree.
        - `make eval`: F1 only, once. Pass = a run directory with
          fingerprint.md and a surface hash matching the current tree.
    </validation_ladder>

    <artifact_contract>
        - `current_state.md`: the handoff and the ledger. One row per
          follow-up with status, date, what was verified and against which
          file. It must let a fresh agent resume without chat history.
        - Repaired doc bundles: canonical doc.json, rendered clean, edited by
          block id.
        - Eval run directories: generated by a suite run, never hand-edited;
          prior runs kept as evidence.
    </artifact_contract>

    <acceptance_gates>
        - `follow_up`: its ladder entries green, current_state.md row updated
          with the verification note.
        - `sitting`: every touched bundle renders, backlinks rescanned, links
          check clean, current_state.md carries the next action.
        - `objective`: all four follow-ups landed or explicitly closed with a
          recorded rationale; final current_state.md marked COMPLETE.
    </acceptance_gates>

    <report_contract>
        - No separate report: current_state.md IS the report for this
          objective.
    </report_contract>

    <current_state_update>
        - Before handoff, update current_state.md with: per-follow-up status,
          exact next steps as file paths and block ids rather than
          intentions, uncommitted-tree scope, and open questions with their
          owner.
    </current_state_update>

    <blocked_or_failed_handoff>
        - If blocked on a decision (F1 is, by design), record the decision
          needed, who owns it, and what unblocks immediately once it is made.
        - If a repair reveals the premise was wrong, correct the premise in
          this bundle and say so in current_state.md; do not write a doc to
          match a premise the code contradicts.
    </blocked_or_failed_handoff>
</validation_and_handoff>
